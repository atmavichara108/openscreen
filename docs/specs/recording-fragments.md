# Спека (в работе): предпросмотр падает на длинной GUI-записи — фрагментация потока

Дата: 2026-11-19. Ветка: `task/adapt-korabl-20261118`. Статус: ФАКТЫ собраны,
root cause не добинен, репро + правка — следующий шаг.

## Симптом (жалоба владельца, прогон Лабы)

GUI-запись 3840×2160, 628 с (`recording-1795111974748.mp4`, 74.7 МБ) открывается
в редакторе ошибкой: «Предпросмотр остановлен… MEDIA_SDK_NETWORK (2);
PIPELINE_ERROR_READ; FFmpegDemuxer: demuxer seek failed». Ассет импортируется
с `codec: "unknown", fps: 0`. Сам файл цел: ffmpeg читает кадры (на 5 с и 300 с),
moov в начале, гонки записи нет.

## Факты (мои замеры 19.11)

- Структура файла: **5 боксов** — `moov, moof(×1), mdat(74.5 МБ), mfra` — ОДИН
  фрагмент на все 628 с. CLI-запись (6 с, рабочая) — 4 фрагмента.
- Ключевые кадры в потоке ЕСТЬ: в первых 30 с — 20 I + 554 P (≈ IDR раз в 1.5 с).
- Но полный проход ffprobe по файлу находит **0** I-кадров: сканер задыхается
  внутри единственного mdat — тот же путь, что и предпросмотр.
- Helper-бинарь не устарел: `openscreen-pipewire-helper` (18.11 21:22) содержит
  `frag_keyframe` и `min_frag_duration` (проверено strings).
- В helper'е заданы `movflags +frag_keyframe+empty_moov+default_base_moof+delay_moov`,
  `min_frag_duration 1000000`, `flush_packets 1` (`encoder.rs:1316`) — то есть
  резать фрагменты по ключевым кадрам хотя бы раз в 1 с ДОЛЖЕН, но не режет.

## Гипотезы (проверяемые)

H1. IDR-NAL'ы есть в потоке, но пакеты не помечены `AV_PKT_FLAG_KEY` на выходе
    кодера (open-GOP/recovery point) → `+frag_keyframe` не срабатывает.
    Проверка: `ffprobe -show_packets -show_entries packet=flags` (K-флаг) на
    короткой GUI-записи.
H2. GUI-путь и CLI-путь зовут helper с разными параметрами муксера.
    Проверка: сверить аргументы helper для обоих путей.
H3. Минимум один фрагмент «до delay_moov» + default_base_moof + tfra на 628 с
    ломает seek в Chromium-демуксере независимо от числа фрагментов.
    Проверка: ремукс оригинала (`ffmpeg -i in -c copy out`, moov в конец) и
    открытие проекта на ремуксе (кодек/ fps в ассете); плюс H1/H2.

## План

1. Репро на моей машине: короткая GUI-запись (8–10 с) → инспекция боксов.
2. Проверка H1/H2; правка в `encoder.rs` (периодическая фрагментация:
   `frag_duration`-принуждение + гарантия key-пакетов) — по диффу причин.
3. Сухой прогон: запись → файл с >1 фрагментов → проект открывается без
   `codec: unknown` (проба возвращает кодек и fps).
4. Приёмка вердиктором на другой модели (линия `mistral/codestral-2508`,
   复活ная; при rate limit — `opencode run --session`-resume).
