# Спека (в работе): предпросмотр падает на длинной GUI-записи — фрагментация потока

Дата: 2026-11-19. Ветка: `task/adapt-korabl-20261118`. Статус: ФАКТЫ собраны,
root cause не добинен, репро + правка — следующий шаг.

## Симптом (жалоба владельца, прогон Лабы)

GUI-запись 3840×2160, 628 с (`recording-1795111974748.mp4`, 74.7 МБ) открывается
в редакторе ошибкой: «Предпросмотр остановлен… MEDIA_SDK_NETWORK (2);
PIPELINE_ERROR_READ; FFmpegDemuxer: demuxer seek failed». Ассет импортируется
с `codec: "unknown", fps: 0`. Сам файл цел: ffmpeg читает кадры (на 5 с и 300 с),
moov в начале, гонки записи нет.

## Факты (мои замеры 19.11)

- Структура файла: **5 боксов** — `moov, moof(×1), mdat(74.5 МБ), mfra` — ОДИН
  фрагмент на все 628 с. CLI-запись (6 с, рабочая) — 4 фрагмента.
- Ключевые кадры в потоке ЕСТЬ: в первых 30 с — 20 I + 554 P (≈ IDR раз в 1.5 с).
- Но полный проход ffprobe по файлу находит **0** I-кадров: сканер задыхается
  внутри единственного mdat — тот же путь, что и предпросмотр.
- Helper-бинарь не устарел: `openscreen-pipewire-helper` (18.11 21:22) содержит
  `frag_keyframe` и `min_frag_duration` (проверено strings).
- В helper'е заданы `movflags +frag_keyframe+empty_moov+default_base_moof+delay_moov`,
  `min_frag_duration 1000000`, `flush_packets 1` (`encoder.rs:1316`) — то есть
  резать фрагменты по ключевым кадрам хотя бы раз в 1 с ДОЛЖЕН, но не режет.

## Root cause (доказан репро 20.11)

Воспроизвёл на машине прямыми вызовами helper (окно 3840×2078, 60 fps):
- запрос БЕЗ audio (source window, cursorMode metadata, fps 60): `moof×6 + mdat×6`
  за 8.8 с, 178 кадров, 6 IDR — файл читается целиком;
- тот же запрос С audio (microphone enabled; узла микрофона в PipeWire нет,
  поток пустой) + deferStart: **`moof×1 + mdat×1`** — гигантский фрагмент.

Механизм: фрагментированный MP4 закрывает фрагмент, только когда интерлив-очередь
собрала пакеты всех дорожек к границе фрагмента. Звуковая дорожка, запрошенная но
никогда не отдающая пакетов (микрофон без узла — «node: null» в логе GUI),
удерживает буфер: фрагмент закрывается один раз, на EOF. Результат — один фрагмент
на всю длину записи; Chromium-демуксер внутри него не ищет (`demuxer seek failed`),
предпросмотр падает, хотя файл цел (ffmpeg читает кадры, moov в начале).

Гипотезы H1/H2 сняты репро: ключевые пакеты помечены (6 пакетов с K-флагом),
helper свежий, дело не в версии бинаря — различие даёт только блок audio.

## Что проверено и НЕ работает (20.11)

- Опция муксера `max_interleave_delta=1000000` в `FRAGMENT_OPTIONS` — принята
  словарём, но на фрагментацию не влияет: репро-запись с пустым микрофоном
  по-прежнему даёт `moof×1` (тест take3). Убрана из правки.
- CLI-модель «позднего звука» (`-itsoffset 7`, пакеты с 7-й секунды) фрагментацию
  лишь задерживает (2 фрагмента), но не воспроизводит «ноль пакетов» — полный
  CLI-репро недостижим, репро остаётся на helper (доказанный).

## Правка (план, следующая)

Не создавать звуковую дорожку, источник которой не может отдать пакеты:
в `start_audio` граф PipeWire перечисляется только когда источник назван явно —
а запрос был «микрофон по умолчанию» (`node: null`); на этом хосте дефолта нет,
поток пустой. План: (1) перечислять граф при любом включённом звуке; (2) если
источник не разрешился И в графе нет ни одного capture-узла — источник
пропускать (не стартовать сессию, дорожка не создаётся); (3) warning-событие
приложению (оно уже получает `AudioSource{node:null}`). Альтернатива на всякий
случай: подавать тишину в кольцо, когда поток молчит (как делается на
переполнении, `silence_owed`).

## Правка (реализовано 20.11)

`electron/native/pipewire-capture/src/capture.rs`, `AudioMix::pump`: добавлен
параметр `owed` — долг звуковой дорожки на активных часах записи
(`Capture::elapsed_active()`, пауза вычтена). В stead of `take == 0 → return`
(mёртвый источник замораживал трек) трек теперь дописывает тишину: `owed`
ограничен `SILENCE_CATCHUP_MAX_SAMPLES` (100 мс) на прокачивание, на flush
выплачивается весь долг; `samples_written` — счётчик часов дорожки.

Сухой прогон на машине (helper из сборки):
- запрос с `microphone.enabled` (узла нет) + deferStart: **moof=7**
  (было 1), aac = 465 пакетов (было 0 — дорожка теперь звуковая, тишина);
- запрос без audio (регресс): **moof=9**, как прежде.

## Гипотезы (проверяемые)

H1. IDR-NAL'ы есть в потоке, но пакеты не помечены `AV_PKT_FLAG_KEY` на выходе
    кодера (open-GOP/recovery point) → `+frag_keyframe` не срабатывает.
    Проверка: `ffprobe -show_packets -show_entries packet=flags` (K-флаг) на
    короткой GUI-записи.
H2. GUI-путь и CLI-путь зовут helper с разными параметрами муксера.
    Проверка: сверить аргументы helper для обоих путей.
H3. Минимум один фрагмент «до delay_moov» + default_base_moof + tfra на 628 с
    ломает seek в Chromium-демуксере независимо от числа фрагментов.
    Проверка: ремукс оригинала (`ffmpeg -i in -c copy out`, moov в конец) и
    открытие проекта на ремуксе (кодек/ fps в ассете); плюс H1/H2.
