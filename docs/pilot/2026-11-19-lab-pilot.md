### Захват (штатный код форка, dev-путь)

Проверочный объект — синтетическое окно `LAB-TEST-WINDOW` (HTML с движущимся блоком, часами и цветными полосами), открытое в Chromium: содержимое окна приватное, экраны владельца не используются, кроме отдельно разрешённой записи display 0.

1. **Перечисление источников — PASS.** `electron . sources --json`: 2 дисплея, 10 окон, 2 микрофона, 1 камера перечисляются на X11.
2. **Запись окна — PASS.** `electron . record --window LAB-TEST-WINDOW --duration 10 --json` → `success:true`, файл `~/.config/openscreen/recordings/recording-1795033489326.mp4`: h264 1706×2056, 360 кадров, dropped 0, курсорных сэмплов 187. OCR кадра на 5-й с показывает содержимое тестового окна («LAB-TEST-WINDOW», бегущий счётчик `t = 121.4 s 23:24:54`) — пиксели именно того окна, не чужого.
3. **Прямой X11-путь — PASS, штатно.** Штатный тест `test:pw-audio-timeline:linux` **провалился**: `portal-failed: ScreenCast version: org.freedesktop.DBus.Error.InvalidArgs: Интерфейс "org.freedesktop.portal.ScreenCast" не существует`. Обход предусмотрен кодом (`electron/native/pipewire-capture/src/main.rs:295-303`): при заданном источнике helper идёт в прямой X11 — `backend=x11`, `source-selected sourceKind=window`, запись идёт. Это штатная ветка форка, не мой обход.
4. **Запись реального экрана — PASS (по слову владельца «настоящий»).** `electron . record --display 0 --duration 6` → h264 3840×2160, 99 кадров, dropped 0.
5. **Системный звук — FAIL (тишина).** В контейнере AAC-дорожка есть (10.07 с), но **пакетов в ней 0** (`ffprobe -count_packets` → `nb_read_packets=N/A`; `ffmpeg` → «No filtered frames for output stream»). В логе helper: `[aac] Qavg: nan`. Причина установлена, а не угадана: helper пишет системный звук нативно через PipeWire (`capture_sink=true` → монитор дефолтного sink'а), а на этом хосте ALSA принадлежит **PulseAudio**, в PipeWire-графе реальных узлов нет — другой сервер. Baseline-контроль: тестовый тон (1 кГц, 3 с), отданный в дефолтный sink, на мониторе слышен — `parecord` даёт пик −24 dBFS; то есть граф исправен, молчит именно путь openscreen. Воспроизводимо: `pactl info` → сервер `pulseaudio`; `pw-dump` → только Dummy/Freewheel.
6. **Микрофон и веб-камера — не включались** (приватность владельца; камера off по слову ИЦ).

## ВЕРДИКТ ЦУ

Вердикт — за ЦУ; ниже — факты, на которых вердикт строится, и моя рекомендация (она не заменяет вердикт).

**Факты Лабы:** dev-сценарий на X11 работает — перечисление источников, запись окна и экрана, курсорные данные, экспорт MP4/GIF (60 fps ровно). Три блокера до дистрибутива и один функциональный дефект:

1. **Пакет deb/pacman не собирается** — `incomplete Linux payload`: нет `libonnxruntime.so` (Linux-бинаря нет в релизе форка; upstream-репозиторий из сети Корабля недоступен — 404), нет `whisper-stt-server` и ggml-backend (сборка упирается в отсутствие `vulkan-headers` на хосте).
2. **Системный звук не пишется** на хосте, где ALSA принадлежит PulseAudio: helper пишет звук нативно через PipeWire, в PipeWire-графе реальных узлов нет. Тон на мониторе sink'а при этом слышен — граф PulseAudio живой.
3. **Портал выбора источника на этом хосте не работает** — `org.freedesktop.portal.ScreenCast` не реализован бэкендом portal-gtk; работает только прямой X11-путь (он и используется в прогоне). Это уточняет карту адаптации форка (`docs/adaptation-korabl.md`): «У нас X11 — работают оба пути» — на текущем хосте порталный путь не работает.
4. **Заявленный fps не выдерживается** софтверным кодировщиком (35.7 при 1706×2056, 16.1 при 4K против заявленных 60), при этом `dropped=0` — счётчик не показывает недобор.
5. **Кириллица в CLI-выводе ломается** (mojibake).

**Рекомендация Лабы:** dev-путь считать рабочим и использовать его для пользовательского сценария на X11 (панель по хоткею работает, запись и экспорт работают); для дистрибутива нужно решение линии разработки по двум пунктам — опубликовать Linux-сборку ONNX в релиз форка (как уже сделано для macOS arm64) и/или разрешить сборку whisper без Vulkan для Linux. Системный звук требует либо fallback-захвата монитора PulseAudio, либо явной документации «PipeWire обязателен». До этих решений пакет на машину ставить нечем.

**Что нужно от владельца (одна команда, если блокер whisper снимается):** `sudo pacman -S --needed vulkan-headers` — после этого пересборка whisper-STT и упаковка продолжатся (до отдельного решения по ONNX).
